# Offline engine and saved routes — decision log

Decisions are appended in order. Each entry records the reason and the evidence
that would justify reopening it.

| ID | Decision | Why | Reverse if |
|---|---|---|---|
| OFF-001 | Saved routes use a separate, versioned encrypted value and a dedicated Android Keystore alias. The plaintext codec is bounded to 25 routes and 4 MiB total. | Destinations and full travelled geometry are sensitive. A separate alias isolates them from route history, search history, favourites and credentials. The limits bound parser, memory and SharedPreferences costs while allowing long polyline6 geometry and maneuvers. | Device measurements show the 4 MiB encrypted value causes unacceptable write latency; move the same codec behind the atomic encrypted-file pattern without changing the model. |
| OFF-002 | Schema 2 stores stable id, timestamps, ordered labelled coordinates, profile/avoidance preferences, provider, engine, calculation time, distance/duration, polyline6 geometry, complete maneuver fields, speed limits, route state and offline-recalculable flag. Schema 1 is accepted with `engine = provider` and `offlineRecalculable = false`. | The snapshot must navigate without a fresh request and already has the fields Phase 3 will need. Explicit defaults make the first migration executable and tested instead of merely reserving a version number. | A future schema migration proves one of these values can be derived without ambiguity. |
| OFF-003 | A calculated saved route opens directly from persisted geometry and instructions and does not call the routing provider. Editing unchanged stops retains their stored coordinates; a changed label is resolved through the existing search path. | This makes “save → reopen → start” work without network, prevents labels from resolving to another place days later, and preserves the existing planner for deliberate edits. | The planner gains coordinate-backed stop fields natively; then the temporary coordinator cache can be removed. |
| OFF-004 | Saved-route deviations do not pretend to reroute offline. Until Phase 2/3 supplies an eligible local engine, the UI warns when starting a saved route that following its stored line works offline but deviation recalculation needs network. | Phase 1 has geometry but no local router. A visible limitation is safer than a straight line, silent provider change or false offline claim. | A local engine is enabled by the user and installed coverage contains the requested reroute. |
| OFF-005 | The executable Kotlin APK for this work is `native-android/app`; it compiles the shared `android/app/src/main/kotlin/app/roadstr/{core,feature,service/...}` and shared resources. `android/app` remains the Flutter production host. | This is the composition root that already owns the encrypted history store and live journey gateway. Both Gradle roots compile the shared feature code, so JVM contract tests stay in `android/app/src/test`. | The production launcher cutover changes the composition root. |
| OFF-006 | Phase 2 adds one routing-engine contract and an explicit selector; online providers stay unchanged and Valhalla is an opt-in local implementation. No implicit offline-first policy is introduced. | It preserves current behaviour for everyone who does nothing and keeps provider parsing behind `RoutingResponseProtocol`. | Measurements show the common contract cannot represent a required provider capability without loss. |
| OFF-007 | Package discovery is lazy: the package host is contacted only after the user opens package management or explicitly starts a download. No startup update check, prefetch or automatic background transfer. | This is required by the product privacy boundary and makes opt-in observable and testable. | Only an explicit user-facing setting with equally explicit disclosure is approved. |
| OFF-008 | Routing/map package installation uses resumable `.part` files, SHA-256 verification and atomic rename within the final filesystem. Coverage is derived from signed/verified manifest metadata plus the installed artifact inventory, never from “file exists” alone. | Interrupted or corrupt multi-gigabyte downloads must never become active data. Same-filesystem rename gives a clear installed/not-installed boundary. | Android storage semantics on supported versions fail an atomic-rename device test; use a two-slot journaled install instead. |
| OFF-009 | Default mobile-data policy is Wi-Fi only. A person may explicitly allow a single transfer on mobile data after seeing size and free-space checks; the choice does not enable future automatic downloads. | Packages range from hundreds of MB to multiple GB. This is the least surprising and most conservative default. | Product owner selects another default after documented UX and cost review. |
| OFF-010 | Static-file hosting remains an open owner decision. The app and tools consume a manifest URL/host configured at build or user level; this design does not select a vendor. | Cost, jurisdiction, availability, logs and update policy are product decisions, not implementation details. | The owner records a hosting choice and its privacy/retention terms. |
| OFF-011 | Phase 3 requires one installed Valhalla archive to cover the complete sampled request; it does not union adjacent archives on-device. | `valhalla-mobile` opens one `tile_extract` per engine instance. Treating two touching packages as one graph would create a false-positive coverage promise. Combined coverage must be built as one archive by the package pipeline. | A measured and tested multi-archive graph composition becomes available without copying or merging multi-gigabyte data on the phone. |
| OFF-012 | Package transfers are scoped to the visible package panel. Closing it cancels the stream and keeps the journal/`.part` for an explicit later resume; there is no periodic or hidden worker. | This satisfies user-visible, explicit transfers without adding a foreground-service framework or background network behavior. | Product explicitly approves a notification-backed foreground service and its cancellation/resume UX. |
| OFF-013 | The package transport accepts only credential-free HTTPS, disables redirects and rejects DNS answers containing non-public addresses. Manifest parsing is bounded before activation, and artifacts are checked by SHA-256 plus an actual Valhalla open. | Package metadata controls large downloads and native data. The same SSRF and bounded-input boundary used elsewhere is required here. | A stricter signed-manifest transport supersedes it; public-address and input bounds remain. |
