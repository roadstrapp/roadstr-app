# Legacy snapshot envelope v1

This envelope is the bounded hand-off between a legacy Flutter reader and the
native migration coordinator. It carries a normalized snapshot; it is not a
Hive file format and it does not decode Android Keystore or secure-storage
files by itself.

The relevant implementations are:

- Dart producer: `tools/kotlin_rewrite/legacy_snapshot_envelope.dart`;
- read-only Hive/asset collector:
  `tools/kotlin_rewrite/legacy_snapshot_collector.dart`;
- reproducible encrypted-box generator:
  `tools/kotlin_rewrite/legacy_raw_hive_fixture.dart`;
- Kotlin consumer: `LegacySnapshotEnvelope.kt`.

The Dart chain starts from the exact encrypted Hive 2.2.3 fixture
`legacy_settings_hive_v1.b64`, collects it without mutation, and must produce
the exact `legacy_snapshot_v1.b64` envelope decoded by Kotlin. Both fixtures
contain conspicuously fake keys, wallet URIs and passphrases only.

## Normalization boundary

The controlled Dart reader owns decoding Hive dynamic values. Secure storage
is supplied through an injectable map reader so the test does not claim
Android Keystore compatibility. The collector emits:

- fixed and per-identity Hive keys as UTF-8 key/value strings;
- secure-storage keys in a separate map;
- a normalized identity triple (`publicKeyHex`, `flavor`, `privateKeyHex`);
- asset metadata, never asset bytes.

Existing top-level strings remain byte-for-byte strings. Null, booleans,
integers and finite doubles use their locale-independent JSON spelling. Lists
and maps become canonical JSON; map keys must be strings and are recursively
sorted. Unknown objects, non-finite doubles, nesting deeper than 32 levels and
graphs exceeding 100,000 visited values fail closed without rendering values
in errors. The native validator still checks known keys, identity bindings,
asset paths and checksums after decoding; the envelope codec is not a
substitute for semantic validation.

Asset collection is explicit rather than recursive: only named regular files
below `kokoro/`, `piper/` and `espeak-ng-data/` are hashed. Traversal,
duplicates and symbolic links fail closed; absent optional files are skipped.

## Binary layout

All integers are signed big-endian. Strings are strict UTF-8 and are prefixed
with a 32-bit byte length. A nullable string uses length `-1` for null.

| Field | Encoding |
|---|---|
| magic | 8 bytes, ASCII `RSTRMIG1` |
| envelope format | int32, currently `1` |
| snapshot schema | int32, currently `1` |
| ordinary map | count int32, then sorted key/value strings |
| secure map | count int32, then sorted key/value strings |
| identity | nullable public key, flavor and private key strings |
| assets | count int32, then path string, size int64 and checksum string; sorted by path, size and checksum |
| integrity | SHA-256 of every preceding byte, 32 raw bytes |

Decoders require exact end-of-body after the final asset. Duplicate map keys,
duplicate asset paths, negative/oversized counts, malformed UTF-8, trailing
bytes, truncation, an unknown envelope version and a digest mismatch all fail
closed.

## Bounds

- envelope: 64 MiB including digest;
- each map: 512 entries;
- key: 256 UTF-8 bytes;
- ordinary value: 4 MiB;
- secure value and identity field: 64 KiB;
- assets: 256 records;
- asset path: 1024 UTF-8 bytes;
- asset size metadata: 0 through 4 GiB.

Kotlin encoding computes the complete bounded size before allocating its output
buffer. Dart writing enforces the envelope cap incrementally. Decoding checks
lengths before allocating or reading each field.

## Integrity and trust

The trailing digest detects corruption and accidental framing differences. It
does not authenticate an attacker-controlled envelope. A production bridge
must keep the bytes inside app-private IPC/storage, and migration must still
derive and compare the Nostr public key before committing. Errors identify the
failed rule without including values or secrets.

## Reproducing the fixture

From the repository root:

```sh
dart run tools/kotlin_rewrite/generate_legacy_snapshot_fixture.dart
dart run tools/kotlin_rewrite/generate_legacy_snapshot_fixture.dart --check
dart run tools/kotlin_rewrite/generate_legacy_hive_fixture.dart
dart run tools/kotlin_rewrite/generate_legacy_hive_fixture.dart --check
flutter test test/legacy_snapshot_envelope_test.dart \
  test/legacy_snapshot_collector_test.dart
cd android && ./gradlew :app:testDebugUnitTest \
  --tests app.roadstr.migration.LegacySnapshotEnvelopeTest
```

Each generator prints base64 to stdout and does not write a file. `--check`
compares generated bytes with its committed fixture. The raw-fixture generator
uses unique deterministic IVs solely to make test bytes reproducible;
production `HiveAesCipher` retains its random-IV behavior.

## Evidence boundary

This proves an actual synthetic Hive 2.2.3 binary can be encrypted, reopened
with the exact key, normalized without mutation and transported
deterministically to Kotlin. It covers all 42 audited fixed Hive keys, one
instance of each of the three dynamic prefixes, all nine secure keys and six
explicit synthetic assets. Inspection also confirms key names remain visible
metadata while fixture values are encrypted.

It does not prove that boxes copied from supported installed releases,
historical `flutter_secure_storage` data or Android Keystore keys can be read.
Those controlled signed-install fixtures remain the blocking M2 evidence.
