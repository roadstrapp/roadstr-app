# Legacy snapshot envelope v1

This envelope is the bounded hand-off between a legacy Flutter reader and the
native migration coordinator. It carries a normalized snapshot; it is not a
Hive file format and it does not decode Android Keystore or secure-storage
files by itself.

The two implementations are:

- Dart producer: `tools/kotlin_rewrite/legacy_snapshot_envelope.dart`;
- Kotlin consumer: `LegacySnapshotEnvelope.kt`.

Both runtimes execute the exact committed synthetic fixture
`android/app/src/test/resources/parity/legacy_snapshot_v1.b64`. The fixture
contains conspicuously fake keys, wallet URIs and passphrases only.

## Normalization boundary

The eventual legacy reader owns decoding Hive dynamic values and secure
storage. It emits:

- fixed and per-identity Hive keys as UTF-8 key/value strings;
- secure-storage keys in a separate map;
- a normalized identity triple (`publicKeyHex`, `flavor`, `privateKeyHex`);
- asset metadata, never asset bytes.

Scalar Hive values use their locale-independent JSON spelling. Lists and maps
use JSON. Existing string values remain strings. The native validator still
checks known keys, identity bindings, asset paths and checksums after decoding;
the envelope codec is not a substitute for semantic validation.

## Binary layout

All integers are signed big-endian. Strings are strict UTF-8 and are prefixed
with a 32-bit byte length. A nullable string uses length `-1` for null.

| Field | Encoding |
|---|---|
| magic | 8 bytes, ASCII `RSTRMIG1` |
| envelope format | int32, currently `1` |
| snapshot schema | int32, currently `1` |
| ordinary map | count int32, then sorted key/value strings |
| secure map | count int32, then sorted key/value strings |
| identity | nullable public key, flavor and private key strings |
| assets | count int32, then path string, size int64 and checksum string; sorted by path, size and checksum |
| integrity | SHA-256 of every preceding byte, 32 raw bytes |

Decoders require exact end-of-body after the final asset. Duplicate map keys,
duplicate asset paths, negative/oversized counts, malformed UTF-8, trailing
bytes, truncation, an unknown envelope version and a digest mismatch all fail
closed.

## Bounds

- envelope: 64 MiB including digest;
- each map: 512 entries;
- key: 256 UTF-8 bytes;
- ordinary value: 4 MiB;
- secure value and identity field: 64 KiB;
- assets: 256 records;
- asset path: 1024 UTF-8 bytes;
- asset size metadata: 0 through 4 GiB.

Kotlin encoding computes the complete bounded size before allocating its output
buffer. Dart writing enforces the envelope cap incrementally. Decoding checks
lengths before allocating or reading each field.

## Integrity and trust

The trailing digest detects corruption and accidental framing differences. It
does not authenticate an attacker-controlled envelope. A production bridge
must keep the bytes inside app-private IPC/storage, and migration must still
derive and compare the Nostr public key before committing. Errors identify the
failed rule without including values or secrets.

## Reproducing the fixture

From the repository root:

```sh
dart run tools/kotlin_rewrite/generate_legacy_snapshot_fixture.dart
dart run tools/kotlin_rewrite/generate_legacy_snapshot_fixture.dart --check
flutter test test/legacy_snapshot_envelope_test.dart
cd android && ./gradlew :app:testDebugUnitTest \
  --tests app.roadstr.migration.LegacySnapshotEnvelopeTest
```

The first command prints base64 to stdout and does not write a file. `--check`
compares generated bytes with the committed fixture.

## Evidence boundary

This proves deterministic Dart-to-Kotlin transport, complete logical-key
coverage for the audited app, limits and corruption handling. It does not yet
prove that a real encrypted `settings.hive`, historical
`flutter_secure_storage` data or an Android Keystore key can be read. Those
controlled installed-app fixtures remain the blocking M2 evidence.
